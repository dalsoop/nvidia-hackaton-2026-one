# cuAlign — 왜 치아 이동 계획을 에이전트로 만드는가

cuAlign은 치과의사가 말로 전달한 조건을 바탕으로 투명교정의 **치아 이동 단계 계획(staging)** 초안을 만들고,
계산 도구로 검증한 뒤 문제가 있으면 다시 계획하는 AI 에이전트다.
의사는 3D 결과를 보며 조건을 수정하고 여러 안을 비교한다. 진단·처방과 최종 판단은 의사의 몫이다.

## 투명교정과 스테이징

투명교정은 일련의 투명한 장치를 순서대로 착용해 치아를 이동시키는 방식이다.
디지털 계획에서는 현재 치아 배열과 목표 배열 사이를 여러 중간 단계로 나눈다. 이 단계와 이동 순서를 설계하는 일이 스테이징이다.
원내에서 스캔·계획·제작을 연결하는 소프트웨어도 제공되고 있다.
[3Shape Clear Aligner Studio 소개](https://www.3shape.com/ko/studio-apps) 참고(접근 2026-09-24).

cuAlign에서 다루는 질문은 “어떤 모습으로 끝낼까?”뿐 아니라 “주어진 조건 안에서 어떤 순서로 이동시킬까?”다.
PoC는 치열 확장, 치아 사이 공간 확보를 위한 IPR, 두 방법의 병행, 발치를 가정한 계산안을 지원한다.
어떤 치료가 환자에게 필요한지를 에이전트가 결정하는 것이 아니라, 의사가 허용한 조건 안의 계획 초안을 비교한다.

## 줄이고 싶은 작업

원내 제작은 실제로 존재하는 작업 흐름이다. 국내 치과가 투명장치용 모델을 병원 내에서 출력하는 사례도 있다.
[Formlabs의 연세수치과 사례](https://formlabs.com/kr/blog/form4b-yonsei-soo-dental-clinic/) 참고(접근 2026-09-24).
이 사례는 제조사 고객 사례이며, cuAlign의 효과를 검증한 자료는 아니다.

우리가 줄이려는 것은 계획을 검토하고, 조건을 바꾸고, 다시 계산해 확인하는 반복이다.
기존 소프트웨어의 자동화 기능 유무가 아니라 **대화로 조건을 전달하면 계획·검증·수정이 연결되는 경험**에 초점을 둔다.
의사가 실제로 얼마나 많은 시간을 이 반복에 쓰는지, cuAlign이 얼마나 줄일 수 있는지는 아직 검증해야 할 가설이다.

원내 제작과 장치 직접 출력은 같은 뜻이 아니다. 출력한 치아 모델을 이용하는 제작과 장치 형상 자체의 출력은 구별해야 한다.
현재 cuAlign의 치아별 STL은 계획 검토용 형상이며, 제작용 모델이나 착용 장치로 바로 쓸 수 있음을 검증한 파일이 아니다.

## 왜 에이전트인가

예를 들어 의사가 “발치 없이 12개월 안에, 앞니 먼저”라고 요청했다고 하자.
에이전트는 조건을 정리하고, 허용된 공간 확보 전략을 고른 다음 목표 배열과 중간 단계를 계산한다.
계산 도구가 공간 부족·겹침·이동량·단계 수 조건의 위반을 반환하면, 다른 허용안을 시도하거나 의사에게 판단을 요청한다.

**조건 확인 → 계획 → 도구로 검증 → 허용 범위 안에서 재계획 → 의사 검토**가 핵심 흐름이다.
조건을 만족하는 안이 없으면 그 사실을 설명해야 하며, 발치 금지 같은 조건을 임의로 풀어 성공을 만들어서는 안 된다.
기간 역시 실제 치료 예측이 아니라 단계 수와 착용 주기로 환산한 계획상 값이다.

이렇게 결과에 따라 다음 행동이 달라지고 여러 계산 도구를 이어 써야 하므로, 단순 질의응답을 넘어선 에이전트의 역할이 생긴다.
3D 화면은 그 결과를 검토하는 수단이지, 에이전트의 계획·검증을 대신하는 애니메이션이 아니다.

## 대회와의 연결

[공식 대회 안내](https://fastcampus.co.kr/NVIDIA_hackathon)는 목표에 따라 계획하고 도구를 호출하는 에이전트와
산업 현장의 문제 해결을 강조한다(접근 2026-09-24).
cuAlign은 이 요구를 조건에 따른 계획·검증·재계획으로 보여주려는 프로젝트다.
NVIDIA 도구의 개수보다는 각 도구가 실제 실행 흐름에서 맡는 역할을 설명하는 데 중점을 둔다.
구체 연결은 [NVIDIA 활용](NVIDIA_STACK.md)에 정리되어 있다.

## 지금 가능한 것과 앞으로의 목표

PoC에는 NAT·Nemotron/NIM을 통한 도구 호출과 다섯 시나리오의 실호출 기록이 있고,
계산 결과를 보는 3D UI, 단계별 치아 STL 출력, Guardrails 대화 검사 경로가 구현되어 있다.
다만 치아의 평행 이동을 계산하는 기하 PoC이며, 힘·조직 반응·고정원 효과나 실제 치료 결과를 검증한 시스템은 아니다.
OpenShell은 별도 정책 실험 단계이고, 스캔 자동 분리 모델의 추론은 실행 검증되지 않았다.

전체 제품 목표에는 **투명교정 장치 자체의 출력 파일**까지 포함한다.
예선은 스테이징을 중심으로 대화·계획·검증·비교·수정을 보여주는 데 집중하고,
장치 형상 생성은 별도 기술 검토로 둔다. 한 덩어리 스캔 입력과 직접 3D 조작은 예선 필수가 아니다.

구체적인 제품 요구사항은 [PRD](PRD.md), 현재 구현과 기술적 한계는 [TRD](TRD.md)를 참조한다.
