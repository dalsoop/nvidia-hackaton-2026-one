# cuAlign 기술 요구사항

> 아키텍처·계산 방식·데이터 계약·검증 기준을 정의한다. 2026-09-25 기준.
> 제품 범위는 [PRD](PRD.md), 파일별 역할은 [코드 안내](CODE_MAP.md)를 참조한다.

## 1. 기술 방향

목표는 자연어 조건이 실제 단계 계획과 검증 결과로 이어지고, 수정해도 조건이 유지되는 실행 흐름이다.
에이전트는 조건 해석·도구 선택·결과 설명을 담당하고, 계산 함수는 좌표·단계·검증 결과를 생성한다.
현재 구현을 기준으로 구조를 설명하며, 아직 충족하지 못한 요구사항은 현재 구현과 구분해 표시한다.
현재 스택·폴더·함수 형태는 팀의 영구 개발 규칙이 아니다. 제품 수용 기준을 유지하면서 팀이 구조를 개선·교체할 수 있다.

### 혼동하기 쉬운 전제

- 분리된 치아 STL 입력과 원본 구강 스캔 자동 분리는 다른 기능이다.
- 규칙 통과는 의사 승인이나 실제 치료 결과 검증을 의미하지 않는다.
- 단계별 치아 STL은 직접 착용하는 장치 셸 파일이 아니다.
- Guardrails의 입력 차단·출력 후 경고·검사 오류 처리는 서로 다르다.
- 현재 공유 메모리 저장소는 다중 사용자 격리나 영속 저장의 완성이 아니다.

## 2. 현재 아키텍처와 기술 선택 이유

웹 UI → NAT 대화 경로 → 계획 에이전트 → 계산 도구 → 계획 저장소 → API·3D 뷰어·STL 출력으로 연결된다.
계획 에이전트는 최종 선택 후 검토 에이전트를 호출한다. 검토는 저장된 계획 요약을 읽는 제한된 NIM 호출이다. Guardrails는 대화 HTTP 경로를 감싼다.

| 역할 | 현재 구성 | 역할·제약 |
|---|---|---|
| 프론트·클라이언트 | 정적 HTML/JS/CSS, three.js | 대화·3D 통합을 빌드 없이 시연. 최종 프론트 스택은 팀 선택 |
| 서버·백엔드 | NAT FastAPI 워커 확장 | 대화, 결과 API, UI를 한 프로세스로 제공. 분리 시 저장소 연결 계약 필요 |
| 에이전트 실행 | NeMo Agent Toolkit | 계획·검토 역할과 도구 호출 실행 흐름 |
| AI 모델 | Nemotron/NIM | 자연어 해석과 도구 선택. 모델 변경은 같은 시나리오로 재검증 |
| 계산 | numpy/scipy, trimesh, manifold3d | 목표·단계 생성과 기하 검사. LLM이 좌표를 직접 생성하지 않음 |
| 데이터 저장 | 메모리 STORE, 계획 JSON 쓰기 | PoC 실행 중 결과 공유. 다중 세션·재시작 복원 요구가 생기면 보강 필요 |
| 인증 | 사용자 인증 계약 없음 | 공개·다중 사용자 운영을 선택하면 별도 설계 |
| 대화 범위 검사 | NeMo Guardrails | 진단·처방 요청 등 범위 검사. 모든 출력의 사전 차단을 보장하지 않음 |
| 실행 격리·규칙 자산 | OpenShell 정책, Skill·스캔 리포트 | 정책 실험·규칙 전달 자료. 서버 전체 샌드박스 통합은 미검증 |
| 배포·운영 | uv, Dockerfile, CI, 로그 | 소스 체크아웃 실행 기준. Docker Linux arm64 빌드·서버 검사 결과는 VERIFICATION 참조 |

NVIDIA 구성별 코드와 실행 근거는 [NVIDIA 활용](NVIDIA_STACK.md)을 참조한다.

## 3. 코드가 실제로 수행하는 계산

| 항목 | 현재 구현 | 한계 |
|---|---|---|
| 입력 | 상악 치아별 STL 또는 합성 샘플. 내부 Universal 번호 사용 | 단일 스캔 추론 연결 미완료 |
| 목표 생성 | 치열궁·치아 폭으로 배열하고 전략별 공간량·활성 치아 변경 | 환자별 임상 목표를 검증한 모델이 아님 |
| 단계 생성 | 동시·앞니 먼저·순차 그룹의 이동을 선형 보간 | 평행 이동만 지원. 최적 순서 탐색·힘/조직 반응 예측 아님 |
| 기간 | 단계 수 × 고정 착용 일수 ÷ 월 환산 일수 | 실제 치료 기간 예측 아님 |
| IPR | 배치용 폭·확보 공간 수치 조정 | 원본 치아 메시를 절삭하지 않음 |
| 충돌 | 번호상 이웃 치아 볼록껍질의 교집합, 초기 겹침에 따른 임계치 | 모든 쌍의 충돌 0 보장이 아님 |
| 수정 | 부모 조건에 명시적 변경을 적용해 새 ID·부모 ID 기록 | 재시작 후 메모리 복원은 미지원 |
| 비교 | 공통 제약 전체를 유지하며 허용 전략별 계획 생성 | 기하 PoC이며 임상적 우열 평가 아님 |
| 출력 | 치아 메시를 평행 이동해 `stage_NN/<치아번호>.stl`로 ZIP 저장 | 장치 셸·베이스·절삭된 IPR 형상 없음 |

근거 파일: `core/planner.py`, `case.py`, `limits.py`, `store.py`, `agent/register.py` (모두 `src/cualign/` 아래).
계산 상수는 PoC의 규칙 설정값이며 모든 환자에 적용되는 보편적 기준이 아니다.

## 4. 데이터·상태 계약

아래는 현재 구현한 계약과 남은 한계다.

| 계약 | 필요한 동작 | 현재 간격 |
|---|---|---|
| 공통 제약 | 케이스의 확인된 조건을 계획·비교·수정·검증에 동일하게 전달 | Constraints 스냅샷·명시적 패치. 자연어 해석의 정확도는 모델에 의존 |
| 계획 식별 | 케이스·조건·목표·단계·위반·파일을 계획에 연결 | 고유 ID·parent_plan_id·조건 스냅샷을 저장 |
| 단위·번호 | 입력·대화·뷰어·파일의 번호 체계와 단위를 일치시킴 | Universal 사용, 분리 어댑터에 FDI 변환 존재 |
| 진행·결과 | 도구 진행과 최종 결과를 구분하고 3D·다운로드와 연결 | plan_selected 이벤트로 연결. UI는 요청·케이스·조회 순서를 확인 |
| 상태 | 규칙 통과·위반·조건 확인 필요·실행 오류·의사 검토를 구분 | 규칙 passed·review 상태·approval을 별도로 저장/표시 |
| 내보내기 | 선택한 계획과 파일 일치, 파일 종류 명시 | 현재 계획 버전의 승인 검사. 규칙 위반·검토 실패는 승인 불가 |
| 저장·격리 | 채택한 운영 범위에 맞춰 세션 경계와 저장 수명 정의 | 활성 케이스와 결과가 프로세스 전역 |

공통 제약·계획 이벤트·부모 이력·승인 출력은 구현했으며 실제 NIM의 종단간 재현은 추가 확인이 필요하다.
규칙 기반 폴백은 별도 실행 모드로 표시하고, 에이전트 실호출 성공 증거로 집계하지 않는다.


### 현재 계획 계약 (2026-09-25)

`core/constraints.py`의 Constraints는 비발치 여부, 고정 치아, IPR 제외 치아,
IPR 면당 한도(0~0.25mm, PoC 상한), 단계 상한, 이동 순서를 저장한다.
비교·수정·단계 생성·검증이 같은 값을 사용한다. 패치의 생략 필드는 유지하며,
치아 목록 []는 해제, stage_cap:null은 상한 해제다. 고정 치아의 발치도 거부한다.

웹 요청의 `cualign` 필드에 request_id·case_id·base_plan_id·조건 패치를 전달한다.
서버가 케이스·부모를 검사하고 요청 컨텍스트를 NAT 하위 작업에 전달한다.
새 목표와 계획은 해당 요청에 속하며, 선택한 부모에서 새 ID로 파생한다.
같은 조건을 비교한 후보들도 현재 선택 계획을 기준으로 생성했으면 같은 부모를 기록한다.
parent_plan_id와 constraints는 계획 API·저장 JSON에 포함된다. 부모를 덮어쓰지 않는다.

에이전트의 `select_plan` 도구가 이번 요청에서 생성한 최종 계획을 명시적으로 선택한다.
서버는 기존 /chat/stream 종료 시 `plan_selected` SSE 이벤트로
schema_version=1, request_id, case_id, plan_id, parent_plan_id, review를 전달한다.
후보는 있지만 선택하지 않았다면 plan_error를 보낸다. plan_context는 최신 조건을 전달한다.
UI는 자연어 ID 검색을 하지 않으며, 이전 요청·케이스 이벤트와 늦은 조회 응답을 무시한다.
수동 선택·규칙 폴백도 같은 조회/표시 경로를 사용한다.

review.status는 not_requested/running/passed/failed/skipped이고 계산 passed와 독립적이다.
reviewer는 ReAct 도구 루프 대신 저장 계획의 요약을 NIM에 전달한다.
요청 단위 최대 2회, 호출당 20초, 전체 40초이며 결과를 저장해 재호출 시 반환한다.
NAT NIM의 num_retries=1(최초 시도 포함)로 중첩 재시도를 막는다.
CLI는 HTTP 요청 컨텍스트가 없으므로 계획별 저장 결과로 중복 검토를 막는다.
검토 실패는 계획 결과와 함께 화면에 표시하며 승인할 수 없다.

의사 확인 후 POST /api/plans/{id}/approval (confirmed=true)로 승인하고 DELETE로 취소한다.
규칙 통과 및 review passed 또는 명시적 규칙 폴백 skipped만 승인 가능하다.
승인은 현재 계획 내용의 해시에 귀속하고 자식 계획으로 상속하지 않는다.
ZIP API·export_stl 도구는 요청마다 승인과 해시를 검사하며 미승인은 HTTP 409/도구 오류다.
에이전트에 승인 도구는 제공하지 않는다. CLI --export는 미승인 출력을 거부한다.
로컬 단일 사용자 승인 기록이며 의사 신원 인증·재시작 복원은 제공하지 않는다.

## 5. 오류·안전 동작

이전 검토 에이전트에서 빈 응답·ReAct 파싱 실패와 반복 호출이 관측됐다. 현재 구현은 제한된 검토 호출로 교체했다. 최종 응답이 반환돼도 중간 오류가 없었다는 뜻은 아니다.
재현 조건·영향·수정 확인 기준은 [알려진 문제](KNOWN_ISSUES.md)에 기록한다.

현재 입력 범위 레일은 차단 판정 시 에이전트를 실행하지 않는다. content safety 입력은 기본 경고 모드다.
스트리밍 출력은 이미 전달한 답을 사후 검사·경고하며, 검사 오류·타임아웃은 ERROR 표시 후 진행한다.
미들웨어는 키 설정과 활성화 옵션에 따라 꺼질 수 있고 대화 경로를 대상으로 한다.
따라서 계산 API·파일 출력까지 동일한 보호가 적용된다고 주장하지 않는다.

팀 구현에서는 모델 실패·검사 불가·계산 실패·규칙 위반을 서로 구분해 표시한다.
금지 조건 유지와 파일 출력 정책은 계산·서버 계약에서도 다루며, Guardrails 하나로 대체하지 않는다.
예선에서 검사 불가 시 계속 진행할지 중단할지는 팀이 명시적으로 결정할 운영 항목이다.

## 6. 선택적 확장과 별도 검토

세그먼테이션은 예선 필수가 아니다. 필요할 때 공개 모델의 샘플 추론부터 검증하는 경로를 제안한다.
ToothGroupNetwork는 추론용 `challenge_branch`를 안내하며 현재 어댑터의 `inference_mid.py`도 그 브랜치에 있다.
명시 라이선스는 확보하지 못했다. MeshSegNet은 README에 상·하악 학습 모델과 코드 MIT 배포를 명시하지만,
가중치·종속 코드 조건은 별도 확인이 필요하다. 현재 어댑터의 모델 추론은 실행 검증되지 않았다.
출처(접근 2026-09-24): [ToothGroupNetwork](https://github.com/limhoyeon/ToothGroupNetwork),
[추론 브랜치](https://github.com/limhoyeon/ToothGroupNetwork/tree/challenge_branch),
[MeshSegNet](https://github.com/Tai-Hsien/MeshSegNet#readme).

장치 형상 생성은 전체 제품 목표를 위한 별도 기술 검토다. 셸 설계, 대상 제작 도구의 입력 조건,
파일·단위·형상 검사 방법을 확인해야 한다. 예선 스테이징 완료 조건에는 포함하지 않는다.
ZIP 생성 성공을 장치 제조 준비 완료로 판단하지 않는다.

## 7. 재현과 검증

확인 기준 코드: `87f4a221569ac9307d6ca2d9a082f4c95be0067a`.
기반 코드의 기존 테스트는 18개이며, 패키징·API 회귀 검사 추가 후 2026-09-24 새 환경에서 총 22개가 통과했다.
2026-09-25 조건·계획 식별·검토·승인 검사를 추가해 총 39개가 통과했다.
자세한 실행 결과는 [재현 검증](VERIFICATION.md)을 참조한다. 계산 코어·NAT 구성/등록·Guardrails 구성·
라벨 기반 분리·파서 가드를 확인하는 테스트다. 모델 실호출, UI, 임상 결과, Docker 배포의 검증을 대신하지 않는다.

PoC 체크아웃에서 실행:

```sh
uv sync --frozen --extra dev
uv run pytest -q -p no:warnings
uv run nat validate --config_file configs/workflow.yml
uv run cualign plan "발치 없이 12개월 안에" --case moderate
uv run cualign serve
```

마지막 서버의 에이전트 실행은 NVIDIA 키 설정이 필요하다. 키 값은 커밋·로그에 넣지 않는다.
기존 로그와 벤치마크는 당시 코드·모델·설정의 관측이며 최신 재실행이나 임상 성과로 소개하지 않는다.

| 검증 묶음 | 통과 기준 |
|---|---|
