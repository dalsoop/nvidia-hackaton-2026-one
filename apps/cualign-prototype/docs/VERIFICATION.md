## 추가 실행 검증

검증 대상은 팀 이관 브랜치 코드 `0d02a29`다. 기존 `docs/demo/`의 시나리오 기록은 덮어쓰지 않았다.

| 검사 | 방법 | 결과 |
|---|---|---|
| Docker 빌드 | 추적 파일만 `git archive HEAD`로 전달하여 Dockerfile 빌드 | 잠금 파일 기반 설치 성공. 키·개인 가상환경 미포함 |
| Docker 서버 | 기본 NAT 서버 실행, 로컬 포트로 HTTP 요청 | UI·JS·케이스 HTTP 200, 규칙 계획 7단계·ZIP 내 STL 98개 |
| 브라우저 3D | Chromium headless, 소프트웨어 WebGL, moderate 선택→규칙 계획→단계 슬라이더 변경 | 치아 14개 표시, 전후 캔버스 변화·스크린샷 육안 확인, pageerror 없음 |
| NIM 단일 케이스 | 같은 Docker 이미지에서 NAT CLI로 moderate / 비발치 / 12개월 / 앞니 먼저 요청 | 89.5초 후 종료 코드 0. 확장안 23단계·IPR안 9단계는 공간 부족으로 실패, 병행안 14단계·계획상 3.2개월은 규칙 통과 |
| 검토 에이전트 | 위 실호출의 전체 로그 점검 | reviewer에서 빈 응답에 따른 ReAct 파싱 오류·재시도 반복 후 최종 검토 메모 반환. 무오류 통과가 아니며 안정성 보완 필요 |

NIM 검사는 승인된 기존 키를 일시적으로 프로세스에 주입했다. 키를 이미지·저장소에 넣지 않았다.
한 케이스 실행 안에서 자동 재시도가 발생했으며, 별도의 추가 케이스는 실행하지 않았다.
브라우저 검사는 규칙 폴백 경로이며 NIM CLI 검사와 별개다.
오류 발췌·재현 조건·영향은 [알려진 문제](KNOWN_ISSUES.md)에 남겼다.

## 인수 안내 보완 후 확인

같은 날짜에 개발 안내·알려진 문제·문서 진입점을 보완했다. 실행 코드·모델 설정은 변경하지 않았다.
오프라인 테스트 22개, 규칙 CLI, wheel 빌드와 필수 자산 18개 검사를 다시 통과했다.
반입 파일 97개에 대한 상대 링크 50개와 기본 토큰 패턴·제외 경로 검사를 통과했다.
이는 문서·패키지 정합성 점검이며 종합 보안 감사나 새 NIM 실호출을 의미하지 않는다.

## 이번에 확인하지 않은 항목

- 브라우저 대화→Guardrails 원격 판정→NIM→3D 표시의 통합 경로와 다섯 시나리오 전체 재실행.
- 하드웨어 GPU·다른 브라우저의 렌더링, Linux amd64 Docker 실행.
- 세그먼테이션 모델 추론·OpenShell 서버 통합·장치 셸 생성·임상 유효성: 검증 범위가 아니다.

계획상 기간은 PoC의 단계 수·착용일 가정으로 계산한 값이며 실제 치료 기간의 검증이 아니다.
최종 자연어 검토 메모의 임상적 정확성도 보장하지 않는다.

## 재현 범위

현재 지원 경로는 **저장소 체크아웃에서 설치·실행**이다. 서버와 벤치마크는 패키지 밖 `configs/`, `guardrails/`, `bench/`도 사용한다.
정적 자산이 wheel에 포함됐다는 사실만으로 wheel 단독 서비스 배포가 지원된다고 해석하지 않는다.
