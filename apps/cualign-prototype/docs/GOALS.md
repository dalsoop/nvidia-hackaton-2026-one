# 목표

> 2026-09-25. 무엇을 목표로 재는지 정의한다. 측정한 값은 [검증 기록](VERIFICATION.md)에, 기술별 연결은 [NVIDIA 활용](NVIDIA_STACK.md)에 둔다.

목표는 두 단계로 나눈다. Phase 1은 예선에서 에이전트가 동작하고 NVIDIA 기술이 실제 실행 흐름에서 쓰인다는 것을 증거로 보이는 목표다.
Phase 2는 이 도구가 의사에게 쓸모 있는지를 재는 제품 목표이며, 이 문서는 그 자리와 형식만 정한다.

## 목표를 적는 규칙

- 목표 하나는 ID, 지표 정의, 목표치, 측정 방법, 현재값으로 적는다. 측정 방법이 없는 목표는 두지 않는다.
- 목표치가 `미정`이면 팀이 아직 합의하지 않은 것이다. 목표치를 정하거나 바꿀 때는 PR 본문에 이유를 쓴다.
- 현재값에는 날짜와 표본 수 n을 붙이고 근거 기록에 링크한다. 모델 호출이 들어간 지표는 n이 작으면 비율로 쓰지 않고 관찰로 쓴다.
- **실행 레코드 보존**: 모든 실측 평가는 `evals/runs/YYMMDDHHMMSS/` 디렉터리에 불변 스냅샷(`metrics.json`, `summary.md`)으로 기록하여 시계열로 관리한다. 기준선(Baseline) 레코드는 `evals/runs/260925152600/`이다.
- **정량적 증감(Delta) 비교**: 실행 간 비교는 `python -m evals.compare <baseline_run_id> <current_run_id>` 명령으로 지표별 Delta와 개선/악화 판정을 자동 계산한다.
- 다른 문서는 통합 상태나 성능 수치를 다시 적지 않고 여기의 목표 ID를 가리킨다.
- 이 지표들은 임상 적합성을 판정하지 않는다. 규칙 통과와 목표 달성은 의사 승인을 대신하지 않는다.

## Phase 2 — 제품 목표

Phase 1이 "데모가 동작한다"를 잰다면, Phase 2는 "의사가 이 초안으로 일을 덜 한다"를 잰다. 목표와 목표치는 팀이 정하며 이 절은 형식과 후보 영역만 둔다.

### 목표 형식

| 칸 | 적는 것 |
|---|---|
| ID | `P2-<번호>` |
| 사용자 가치 | 이 수치가 좋아지면 의사에게 무엇이 나아지는가 |
| 지표 | 계산식과 단위. 분모에 들어가는 표본을 명시 |
| 기준선 | 목표치를 정하기 전에 측정한 현재값과 측정 조건 |
| 목표치 | 기준선 대비 값. 근거를 PR 본문에 |
| 측정 | 재현 가능한 명령이나 절차. 모델 호출 여부 |
| 표본 | 합성 케이스·실제 스캔 등 데이터 출처와 수 |

기준선을 재기 전에는 목표치를 적지 않는다.

### 후보 영역

아래는 논의를 시작하기 위한 영역이며 채택한 목표가 아니다.

| 영역 | 재는 것의 예 |
|---|---|
| 조건 해석 | 자연어 조건을 제약으로 옮긴 정확도 |
| 의사 작업량 | 첫 요청부터 승인까지의 턴 수·수정 횟수 |
| 계획 품질 | 규칙 위반 없는 초안 비율, 참조 계획 대비 단계 수 차이 |
| 시간·비용 | 첫 초안까지 시간, 턴당 모델 호출 수·토큰 |
| 안전 | 처방·확정 문구의 미탐·오탐, 식별정보 차단 |

Phase 1 목표 중 회귀를 막는 것(P1-3, P1-5, P1-10)은 Phase 2에서도 유지한다.
