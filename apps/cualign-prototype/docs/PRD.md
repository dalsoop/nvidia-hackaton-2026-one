# cuAlign 제품 요구사항

> 사용자·해결할 문제·제품 범위·수용 기준을 정의한다. 2026-09-25 기준.
> 구현 현황과 기술적 한계는 [TRD](TRD.md)를 참조한다.

## 1. 제품 요약

cuAlign은 치과의사가 자연어로 전달한 제약과 우선순위를 바탕으로 투명교정 단계 계획 초안을 만들고,
규칙 검증과 대화를 통해 계획을 반복 조정하는 에이전트다.
의사는 3D 결과와 위반 내용을 검토하고, 여러 안을 비교하거나 수정 지시를 내린다. 최종 판단은 의사가 한다.

전체 제품은 검토한 계획을 투명교정 장치 자체의 3D 출력 파일까지 연결하는 것을 목표로 한다.
예선에서는 **스테이징을 중심으로 계획·검증·수정의 반복을 완주하는 것**에 집중한다.
장치 형상 생성은 별도 기술 검토 항목이다. 현재 출력은 단계별 치아 STL이며 완성 장치 파일이 아니다.

## 2. 사용자와 해결할 문제

주 사용자는 투명교정 계획을 검토·조정하는 치과의사다. 초보 의사로 한정하지 않는다.
줄이려는 불편은 조건을 반영하기 위해 소프트웨어의 여러 기능을 직접 조작하고,
결과를 확인한 뒤 다시 조정하는 반복 작업이다.

cuAlign에서는 “발치 없이”, “12개월 안에”, “앞니 먼저” 같은 조건을 대화로 전달한다.
에이전트가 조건을 정리하고 계산 도구를 실행하며, 위반이 있으면 허용된 다른 안을 시도하거나 의사에게 묻는다.
대화의 결과는 설명뿐 아니라 실제 3D 단계 계획·검증 결과·파일에 반영돼야 한다.

이 문제 정의는 기획 의도다. 불편의 빈도, 작업 시간 절감, 임상 효과는 아직 실측하지 않았다.

## 3. 제품 범위

| 구분 | 범위 |
|---|---|
| 전체 제품 목표 | 스캔 입력 → 의사와 대화하며 계획 조정 → 검토 → 투명교정 장치 출력 파일 |
| 예선의 중심 | 분리된 치아·샘플 입력 → 조건 확인 → 전략·단계 계획 → 검증·재시도 → 비교·수정 |
| 예선 결과 파일 | 단계별 치아 STL과 계획·위반 정보. 장치 셸이나 제조 준비 완료 파일은 아님 |
| 선택적 확장 | 한 덩어리 스캔의 자동 분리, 직접 3D 조작 |
| 별도 기술 검토 | 장치 형상 생성, 직접 출력 파일의 검증 |
| 현재 PoC의 제한 | 상악·평행 이동 중심, 앞니 회전·수직 보정 포함. 송곳니·구치 회전, 하악·교합·토크는 미지원 |

선택적 확장과 장치 형상 생성을 예선 핵심 흐름의 선행 조건으로 두지 않는다.
현재 PoC의 제한을 장기 제품 범위로 고정하지 않으며, 예선의 추가 지원 범위는 팀이 개발 여건에 맞춰 합의한다.

## 4. 핵심 개념과 역할

| 개념 | 이 제품에서의 의미 |
|---|---|
| 목표 치열·셋업 | 계획이 도달하려는 치아 배열 초안 |
| 스테이징 | 현재 배열에서 목표까지 이동을 여러 단계와 순서로 나누는 일 |
| 전략 | 조건 안에서 공간을 확보하기 위한 계산안. PoC는 확장·IPR·병행·발치안을 비교 |
| 규칙 검증 | 설정한 공간·충돌·이동량·장수 조건의 위반 검사 |
| 의사 검토 | 계획을 보고 판단·수정하는 과정. 규칙 통과와 별개 |

에이전트는 조건 정리, 도구 호출, 결과 해석, 재시도를 담당한다. 계산 도구는 좌표·단계·위반 정보를 만든다.
의사는 임상 판단과 조건 변경 여부를 결정한다. 에이전트는 진단·처방을 수행하지 않는다.
계산안 제시와 환자에게 필요한 치료의 결정을 구별하고, 금지 조건을 몰래 완화하지 않는다.
기하적 단계 시각화를 실제 치료 결과나 조직 반응의 예측으로 표현하지 않는다.

## 5. 사용자 흐름과 화면의 역할

| 단계 | 사용자 행동 | 화면이 제공해야 할 것 |
|---|---|---|
| 케이스 준비 | 샘플 선택 또는 분리된 치아 파일 업로드 | 입력 상태, 대상 치아와 번호, 3D 초기 상태 |
| 조건 확인 | 기간·금지 조건·우선순위 전달, 필요한 질문에 답변 | 해석한 조건, 부족한 정보 |
| 초안 생성 | 진행을 확인하고 필요한 판단 제공 | 어떤 전략을 시도했는지, 검증 결과와 전환 이유 |
| 검토·비교 | 단계별 결과와 대안을 확인 | 3D 단계, 관련 치아·위반, 전략·장수·계획상 기간의 차이 |
| 수정·재계획 | 특정 치아 고정, IPR 제외 등 지원하는 수정 지시 | 변경 조건과 새 계획, 이전 안과의 구분 |
| 승인·내보내기 | 현재 계획을 의사가 승인한 뒤 다운로드 | 계획별 승인 상태, 승인한 계획과 일치하는 파일, 포함물과 검증 상태 |

선택한 케이스·대화·뷰어·다운로드는 같은 계획을 가리켜야 한다.
진행 요약은 쉽게 읽히게 하고 도구 원문은 필요할 때 펼쳐 본다.
색상 외에도 텍스트·위반 목록으로 상태를 구별한다. 패널 배치와 시각 스타일은 UI/UX 설계에서 구체화한다.

## 6. 기능 요구사항과 수용 기준

| 기능 | 관찰 가능한 수용 기준 |
|---|---|
| 조건 확인·유지 | 이미 받은 조건을 반복 질문하지 않는다. 확인한 조건은 비교·수정·재계획에도 유지된다. |
| 조건을 만족하는 초안 | 조건, 전략, 단계 계획, 검증 결과, 3D 표시가 같은 계획에 연결된다. |
| 허용안 전부 실패 | 실패 이유와 의사에게 필요한 판단을 표시한다. 성공이나 치료 불가능 확진으로 표현하지 않는다. |
| 전략 비교 | 동일한 조건으로 여러 안의 전략·단계·위반을 비교하고 검토할 안을 선택한다. |
| 수정 후 재계획 | 지원 수정이 새 계획에 반영되고 부모 계획을 기록한다. 최종 선택 이벤트로 3D·카드·다운로드를 연결한다. 변경하지 않은 조건을 유지하며 재검증한다. |
| 의사 승인·내보내기 | 승인한 계획만 출력 가능하고 승인 상태를 표시한다. 수정안에 부모 승인을 상속하지 않는다. 파일은 선택 계획과 일치하며 단계별 치아 메시임을 명시한다. |
| 상태·기간 표시 | 규칙 통과·의사 검토·시스템 오류를 구분한다. 기간은 단계 수·착용 주기의 환산값으로 표시한다. |

다섯 핵심 시나리오는 통과·정직한 실패·비교·되묻기·수정이다.
완주 여부와 조건 유지·위반 검출을 확인하며, 단순한 시각적 애니메이션만으로 완료를 판정하지 않는다.

## 7. 팀 검토가 필요한 세부 동작

아래 항목은 제품 운영 정책을 더 구체화할 부분이다. 현재 프로토타입의 규칙 폴백은 검토 미실행을 명시한 후 의사가 승인할 수 있다. 이 확인을 임상 검증으로 표현하지 않는다.

| 항목 | 결정할 내용 |
|---|---|
| 비교 시작 방식 | 최초부터 여러 안을 제시할지, 요청할 때 비교할지 |
| 허용 전략·조건 변경 | 의사가 허용 범위를 확인하는 시점과 변경 동의 방식 |
| 승인 절차 | 승인 버튼·명시적 확인·승인 취소를 프로토타입에 적용. 운영 시 의사 신원 인증·권한 모델은 별도 결정 |
| 실패안 다운로드 | 프로토타입은 규칙 위반·검토 실패의 승인/출력을 제한. 예외적으로 실패안을 내보내는 운영 정책은 별도 결정 |
