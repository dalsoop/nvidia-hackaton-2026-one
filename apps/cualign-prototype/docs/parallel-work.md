# 병렬 세션 운영 방식 — 한 사람이 여러 에이전트 세션으로 이 앱을 고칠 때

2026-09-27~28 이틀 동안 오케스트레이터 세션 하나가 Orca 워크트리 4~10개에 Opus 세션을 띄워 PR 60여 개를 처리했다.
그때 시간을 잡아먹은 것과, 다음에 같은 일을 할 때 처음부터 그렇게 하면 되는 규칙을 적는다.
새 세션은 `HANDOFF.md`·[CODE_MAP](code-map.md) 다음에 이 문서를 읽는다.

## 1. 역할 분리

- **오케스트레이터 하나만 머지한다.** 작업 세션은 PR 까지만 올리고 멈춘다(「머지는 하지 않는다」를 지시문에 매번 적는다). 머지 순서·rebase 지시·8000 서버는 오케스트레이터가 쥔다.
- **8000 은 시연 서버다.** main 체크아웃에서만 띄우고, 작업 세션은 8001~8009 를 쓴다. 8000 에 Playwright 프로브를 쏘지 않는다 — 프로브가 만든 케이스가 시연 화면에 「내 스캔」 잔재로 남았다(케이스 저장은 서버 프로세스 메모리·`out/` 에 남는다).
- **지시문은 워크트리 루트 `TASK.md` 로 준다.** 발사 프롬프트는 「TASK.md 를 읽고 수행해라. git 에 넣지 말고 끝나면 지워라」 한 줄. 긴 프롬프트를 argv 로 넣으면 셸에 타이핑되어 깨진다. 후속 지시는 `orca terminal send --text … --enter` 로 같은 세션에 보낸다.

## 2. 파일 경계 — 충돌을 미리 없앤다

가장 큰 낭비는 **같은 파일을 여러 갈래가 고쳐서 생긴 rebase 반복**이었다. `#164`(직접 이동)는 main 이 움직일 때마다 세 번 다시 맞췄고, 그 동안 다른 갈래 머지를 얼려야 했다.

- `static/app.js` 하나가 3천 줄이라 화면 작업은 거의 전부 여기서 겹친다. 지시문에 **손대는 함수 이름을 열거**하고(예: 「`renderRulesPane`·`renderCondPane` 에 국한」), 다른 세션 영역은 「본문을 건드리지 않는다」로 못 박는다. 새 기능은 `scan-reveal.js`·`drawers.js`·`three-load.js`·`manual.js` 처럼 **새 모듈**로 빼고 `app.js` 에는 훅 한 줄만 둔다.
- 공용 부품(예: `.pulse-dot` CSS)은 **한 PR 이 소유**하고, 쓰는 쪽 PR 은 그 PR 이 머지된 뒤에 발사한다. 아직 없으면 「그 갈래에서 그 블록만 가져오고 PR 본문에 적는다 — 중복 정의 금지」.
- `tests/browser_flow.py` 도 충돌 지점이다. 세션마다 단언을 **끝에 덧붙이게** 하고, 기존 단언의 선택자를 바꾸면 반드시 PR 본문에 적게 한다.
- 머지 순서는 **의존 순 → 겹치는 파일이 적은 순**. 문서만 바꾼 PR 은 순서와 무관하게 먼저 넣는다.

## 3. 머지 절차 — CI 가 끝난 뒤에만

main 이 두 번 빨갛게 됐다. 하나는 팀원 PR 을 CI 결론 전에 넣어서(#174 → #181 로 복구), 하나는 `os.execv` 가짜가 Linux 에서 다음 분기로 흘러서(#172 → #178). 둘 다 **`MERGEABLE` 은 CI 통과가 아니다**를 몰라서 생겼다.

- `gh pr view N --json mergeable,statusCheckRollup` 에서 `cualign-prototype` 잡이 `SUCCESS` 인 것만 머지한다. `mergeable` 만 보고 넣지 않는다.
- CI 는 갈래 하나에 10분 안팎, 동시에 다섯 갈래가 돌면 더 걸린다. **기다리는 동안 다음 지시문을 쓴다** — 폴링은 백그라운드 명령이나 Monitor 로 걸고 이벤트로 받는다.
- 머지 직후 같은 파일을 만진 다른 PR 은 `CONFLICTING` 으로 바뀐다. 그 세션에 「origin/main 위로 rebase, `node --check` 와 `pytest -n 2` 만, browser_flow 는 다시 돌리지 않는다, force-push」를 보낸다. 여러 갈래가 남았으면 **한 번에 전부** rebase 시키고 순서대로 넣는다(한 갈래씩 시키면 갈래 수만큼 CI 왕복이 생긴다).
- 「Head branch is out of date」가 나오면 auto-merge(`gh pr merge --auto --squash`)를 걸어 두면 된다.
- CI `layout` 잡은 루트 md 를 `README|AGENTS|ARCHITECTURE|HANDOFF` 만 허용한다. 문서는 `apps/cualign-prototype/docs/` 에 둔다.
- `api.py`·`export_jobs.py`·`plan_events.py` 등 서버 코드가 바뀐 PR 이 들어가면 8000 을 재시작한다. `static/` 만 바뀌면 새로고침으로 충분하다.

## 4. 기계 부하 — 한 대에서 세션 여섯이 돌 때

CPU 가 100% 에 붙어 Orca 와 터미널이 멎었다. 원인은 세션마다 `pytest -n auto`(38 워커), `browser_flow.py` 4개 동시 실행, 헤드리스 Chrome 의 소프트웨어 WebGL 이었다.

- `pytest -n 2`. 전체 테스트는 PR 직전 한 번, 편집 중엔 건드린 모듈만.
- `browser_flow.py` 는 **PR 직전 한 번**, 서버는 확인 뒤 즉시 내린다. 다른 무거운 실행과 겹치면 30초 대기가 초과돼 거짓 실패가 난다.
- `browser_flow.py` 는 기계 전역 잠금(`%TEMP%\cualign-browser-flow.lock`)으로 한 번에 하나만 돈다. 워크트리가 달라도 둘째는 10초마다 기다리는 중이라고 찍고, 첫째가 끝나면 시작한다(최대 15분, 15분 넘은 잠금은 죽은 실행으로 보고 넘겨받는다).
- 헤드리스(webdriver) 브라우저의 3D 는 10 fps 로 그린다(`app.js` 렌더 루프, `?fps=N` 으로 조정). 사람 브라우저는 그대로 매 프레임.
- 스크린샷은 마지막 한 장씩. 헤드리스 Chrome 을 세션당 하나 이상 띄우지 않는다.
- NIM 실호출은 작업 세션에서 금지(턴은 재생·가짜 스트림으로). 여러 세션이 한 키를 쓰면 429 가 몰려 시연 서버까지 느려진다. 실호출은 오케스트레이터가 재녹화할 때만.

## 5. 검증이 놓친 것 — 사용자 시점으로 찍는다

- `#163` 치아 캡은 헤드리스 스크린샷에서 문제가 안 보였다. 시점이 교합면 위였기 때문이다. 사용자가 본 증상은 잇몸선 높이의 낮은 각도에서만 난다. **재현 스크린샷은 사용자가 봤다고 말한 시점·단계·케이스로** 찍고, 지시문에 카메라 위치를 적는다.
- 「어두운 단면」의 원인은 캡이 아니라 조명(`HemisphereLight` 위쪽 기본값 `+y`, 이 장면은 `z` 가 위)이었다(#184). 원인 후보가 둘 이상이면 물체를 하나씩 숨겨 **먼저 정체를 가른 뒤** 고친다.
- 셋업 턴은 `set_constraints` 도구 이벤트를 안 내고 37초 뒤 한 덩어리로 도착한다(출력 레일). 화면이 「아무것도 안 함」으로 보이는 원인이라 도구 줄을 합성했다(#176). 실 스트림과 재생 둘 다에서 확인해야 한다.

## 6. 환경

- `.env` 는 **체크아웃 루트에서만** 읽는다. 워크트리마다 복사하지 말고 `NVIDIA_API_KEY` 를 Windows 사용자 환경변수로 둔다. 이미 떠 있는 프로세스는 새 환경변수를 못 본다 — 재시작하거나 `[Environment]::GetEnvironmentVariable('NVIDIA_API_KEY','User')` 로 끌어온다.
- `uv run` 은 venv 런처를 거쳐 프로세스가 둘씩 보인다(정상). 서버를 내리면 `nat serve` 도 같이 끝나게 `winjob.py` 가 잡는다(#172).
- 워크트리 venv 는 본 체크아웃 `.venv` 를 `UV_PROJECT_ENVIRONMENT` 로 공유한다. `uv sync` 를 워크트리마다 돌리지 않는다.
- 컴퓨터가 재시작되면 Orca 가 터미널을 새 핸들로 복원한다. `orca terminal list --json` 으로 핸들을 다시 받고, 각 세션에 「이어서 진행」 한 줄을 보낸다. 감시 루프는 다시 건다.

## 7. 지시문 서식

세션이 같은 품질로 보고하게 지시문 끝에 항상 넣는다.

- 공통 규칙(위 2·4 절 요약: 포트, `-n 2`, browser_flow 1회, NIM 금지, 8000 불가침, 머지 금지, TASK.md 삭제).
- 손대는 파일·함수 목록과 **손대지 않는 영역**.
- 검증: 어떤 케이스·단계·시점에서 스크린샷 몇 장, `browser_flow.py` 에 추가할 단언 하나.
- PR 본문 네 절: 바꾼 것 / 결정한 것 / 실행한 검증 / 못 한 것. 결정한 것에는 지시와 다르게 한 이유를 적게 한다 — 이 절이 다음 지시문의 재료가 된다.

## 8. 시연 직전 순서

1. 열린 PR 을 위 3 절대로 전부 넣어 main 을 clean 으로 만든다.
2. 8000 재시작: `uv run --frozen python -m cualign.cli serve --port 8000`(main 체크아웃).
3. 다른 세션의 NIM 호출을 멈춘 상태에서 사용자가 실제 NIM 으로 E2E 를 돈다.
4. E2E 에서 나온 것만 새 갈래로 고친다. 재녹화(`tests/nim_record_samples.py`)는 그 뒤.
5. 제출 스크린샷은 `docs/demo/README.md` 의 장면 목록대로.
